# Corevia 관련 거래처 장려금 결재 서비스 (MVP)

`../hackathon_data`(하위 폴더 포함 전체)를 읽어 워크플로우를 실제로 돌리는 Flask + SQLite 서비스입니다. 운영 중 판단 자료는 Claude 에이전트가 씁니다.

```
pip install -r requirements.txt
python app.py            # http://127.0.0.1:5080
python -m unittest discover -s tests   # 통합 테스트 16개 (실제 API는 부르지 않음)
```

오른쪽 위에서 **접속 역할**(영업팀·재무팀·내부감시팀·영업임원·품질팀·Masil)을 바꿔 가며 시연합니다. 점선 테두리 버튼이 현재 역할이 누를 차례인 버튼입니다. `시연 초기화`는 요청·결재·로그·품질 판정만 지우고 원천 데이터는 건드리지 않습니다.

## AI 에이전트 연결

`service/.env` 파일을 만들고 키를 넣으면 됩니다(git에는 올라가지 않습니다). 환경 변수로 줘도 됩니다.

```
ANTHROPIC_API_KEY=sk-ant-...
```

| 설정 | 기본값 | 뜻 |
|---|---|---|
| `CV_AI` | `on` | `off`면 LLM을 부르지 않고 규칙 기반 문구만 씀 |
| `CV_AI_MODEL` | `claude-opus-5-5` | 에이전트 모델 |
| `CV_AI_EFFORT` | `medium` | 추론 깊이 (`low`~`max`) |

연결 여부는 `데이터 연결` 화면에서 볼 수 있습니다. 키가 없거나 호출이 실패하면 규칙 기반 문구로 대신하고, 그 사실을 감사 로그에 남깁니다.

에이전트는 `agent.py`에 있고 세 지점에서 돕니다. 도구 10개로 원천 데이터를 직접 조회하고, 출력은 JSON 스키마로 고정됩니다. 부른 도구와 출력은 모두 감사 로그에 남습니다.

| 호출 시점 | 하는 일 | 결정하는 사람 |
|---|---|---|
| 결재 대기 진입 | 관련자·한도·리스크·Corevia 현금 근거를 조회해 권고안과 영업팀에 물을 질문 작성 | 재무팀·내부감시팀·영업임원 |
| 영업팀 소명 제출 | 소명이 보류 사유를 풀기에 충분한지, 더 받아야 할 증빙이 무엇인지 평가 | 품질팀 |
| 현금 지급 거절 | 크레딧 대체안 설명과 품목 제외 판단 근거 작성 | 영업팀·재무팀 |

숫자 계산과 상태 전이는 `engine.py`·`workflow.py`의 규칙이 정합니다. 에이전트는 조회·해석·설명만 하고 승인·거절·해제는 사람이 합니다.

## 판단 기준과 근거

| 규칙 | 값 | 근거 |
|---|---|---|
| 동일 관련자 | 대표자·주소·정산계좌 중 2개 이상 일치, 전이 연결, 실제 입금 계좌도 대조 | `data_dictionary.md` §4 |
| 지급 한도 | 거래처별 월 200만 원 이하 영업지원팀 전결, 초과 영업임원 승인. 동일 관련자는 합산 | `approval_authority_policy.md` |
| 결재선 | 재무팀 → 내부감시팀 → 영업임원 | 영업임원은 정책, 재무·내부감시 검토는 이 서비스가 더한 단계 |
| 악성 클레임 보류 | 최근 6개월 '악의적' 판정 3건 이상 | 워크플로우 명세 값 |
| 연체 경고 | 90일 초과 시 결재 화면에 경고 (보류하지 않음) | 자체 설정 |
| 크레딧 | 장려금 100%, 유효 90일, 분할 시 현금 50% | 자체 설정 |
| 크레딧 제외 품목 | 미종결 확정 결함이 있는 제품군 | `qc_claims_cv` · 판단 근거를 감사 로그에 기록 |

등록 정보가 겹치는 것은 소명·감사 대상이며 부정 확정이 아닙니다. 값은 `config.py`에 있습니다.

## 시연 순서 (기준 거래처 D-011, 정산 2026-06)

시나리오마다 시작 전에 `시연 초기화`를 누릅니다. 같은 월·같은 관련자 그룹이 이미 지급(PAID·크레딧 확정)되었거나 원천 데이터에서 '승인'된 달이면 검사 단계에서 중복 지급으로 차단됩니다. 승인과 거절은 모두 재무팀 → 내부감시팀 → 영업임원 순서를 따릅니다.

**시나리오 1 · 정상 작동**

| 단계 | 역할 | 동작 | 결과 |
|---|---|---|---|
| 1 | 영업팀 | 새 요청 → AI 매칭 실행 | D-024 3개, D-037 2개 일치 → 동일 관련자 그룹 |
| 2 | 영업팀 | 합산 한도·리스크 검사 | 합산 3,888,097원 > 한도 2,000,000원 → **AWAITING_APPROVAL**. 연체 29,202,840원은 경고로 표시, AI 권고 작성 |
| 3 | 재무팀 → 내부감시팀 → 영업임원 | 승인 × 3 | **PAID** |

**시나리오 2 · 악성 클레임 보류**

| 단계 | 역할 | 동작 | 결과 |
|---|---|---|---|
| 0 | 품질팀 | `품질 판정` → D-024 선택 → `시연용 예시 3건 등록` | '악의적' 판정 3건 (시연용 입력으로 표시) |
| 1~2 | 영업팀 | 새 요청 → 매칭 → 검사 | **PENDING** · 영업팀·품질팀 알림 |
| 3 | 영업팀 | 소명 제출 | AI 소명 검토가 스레드에 달림 |
| 4 | 품질팀 | 해제 | **AWAITING_APPROVAL** |

**시나리오 3 · 현금 거절 → 크레딧**

| 단계 | 역할 | 동작 | 결과 |
|---|---|---|---|
| 1~2 | 영업팀 | 시나리오 1의 1~2단계 | AWAITING_APPROVAL |
| 3 | 재무팀 | `CASH_SHORTAGE`로 거절 | 근거: Corevia 현금 3개월 연속 감소(218.5억 → 190.8억 원), 이 그룹 연체 2,920만 원. AI가 Masil CH-04 크레딧 대안 제안 → **ALT_PROPOSED** |
| 4 | 영업팀, 재무팀 | 각각 수락 | **CREDIT_SCHEDULED** |
| 5 | Masil | 발주서 번호 입력 | **CREDIT_SETTLED** |

분할안(크레딧 50% + 현금 50%)을 고르면 5단계 뒤에 한 단계가 더 있습니다.

| 단계 | 역할 | 동작 | 결과 |
|---|---|---|---|
| 5 | Masil | 발주서 번호 입력 | **CASH_PENDING** · 재무팀에 이연 현금분 지급 알림 |
| 6 | 재무팀 | 이 그룹 연체 채권 회수 확인 후 지급 전표 번호 입력 | **CREDIT_SETTLED** (분할 정산 완료) |

- D-001처럼 관련자가 없고 지급액이 한도 이하면 **WITHIN_LIMIT**(영업지원팀 전결 범위)로 끝납니다.
- 박준호 D-034에 D-041을 후보로 넣으면 대표자 1개만 일치해 **MANUAL_REVIEW**로 가고, 내부감시팀이 포함 여부를 정합니다.

## 데이터에서 확인한 사실

- 장려금 240건 가운데 한 건으로 200만 원을 넘는 것은 없습니다(최대 1,867,253원). 박상현 그룹은 합산하면 1~6월 내내 한도를 넘습니다(3,888,097~4,870,186원).
- 1,225쌍 중 2개 이상 일치하는 쌍은 박상현 그룹뿐입니다.
- Corevia 월말 현금은 3월 218.5억 원에서 6월 190.8억 원으로 3개월 연속 줄었습니다. 90일 초과 미회수 채권은 62.8억 원(38건)입니다.
- 미종결 확정 결함은 6개 제품군 중 PL-02에만 있습니다(LOT-B-2602-P, 45건, 36,522개). 그래서 크레딧 대상에서 더마 4종만 빠지고 10종이 남습니다. 발주와 lot을 잇는 키가 없어 lot 단위로는 뺄 수 없습니다.
- Masil은 2026-07-21에 Corevia 앞 발주 대금 3,749,760,000원이 나가 약정 하한 30억 원을 밑돌 것으로 재전망됩니다(최저 약 14.7억 원, 보수적 계산). 거절 근거로 쓰지 않고, 크레딧 정산이 Masil 현금에 부담을 주지 않도록 설계하는 데만 씁니다.

## 구현 범위 밖 (설계 단계)

- 과거 1~5월 한도 초과 지급 22,238,349원은 내부감시팀 **사후 검토 등록까지만** 합니다. 환수·재승인 절차는 설계 단계입니다.
- Masil 시스템 연동은 없고, Masil 역할이 발주서 번호를 직접 입력해 확인합니다.
- Corevia↔Masil 발주 대금 차감 정산은 제안이며 양사 합의가 필요합니다.

## 데이터 폴더

`hackathon_data/정책_원본추가/`의 6개 파일은 공식 데이터룸(`04_원본데이터`)에서 복사했습니다: `approval_authority_policy.md`, `data_dictionary.md`, `covenant_terms_ms.md`, `lc0001_payment_term_notice.md`, `sc_purchase_orders_ms.csv`, `fin_ap_aging_ms.csv`.

## 구조

- `data.py` — 파일 탐색·로딩, 파일 인벤토리
- `engine.py` — 관련자 판정 / 합산 한도·요율 / 리스크 / 현금 근거·재전망 / 대안 탐색 (규칙 기반, 근거 행 id 포함)
- `agent.py` — Claude 에이전트 (도구 정의·구현, 도구 호출 루프, 구조화 출력)
- `workflow.py` — 상태 머신, 역할 권한, 알림, 소명 스레드, 품질 판정, 감사 로그(SQLite 트리거로 수정·삭제 차단)
- `app.py`, `templates/` — 화면 (요청함, 새 요청, 요청 상세, 알림, 품질 판정, 감사 로그·CSV, 데이터 연결)
